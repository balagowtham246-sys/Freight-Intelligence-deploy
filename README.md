# Freight Forecasting & Chartering Platform

Constraint-aware vessel, timing and contract decision support for bulk cargo
procurement into India's East Coast ports.

Built against the SIH problem statement in [`Plan/PRB.txt`](Plan/PRB.txt) and
the strategy in
[`Plan/freight-forecasting-platform-plan.md`](Plan/freight-forecasting-platform-plan.md).

## What it does today

**Chartering Advisor** — ranks every way of moving a cargo, with the
constraint arithmetic shown. Transhipment is modelled as a first-class routing
rather than an exception, because for Haldia it usually *is* the answer: the
port takes nothing over 45,000 DWT, while Sandheads has 40-50 m of water a
short distance away.

**Entry Timing** — *when* to fix, not just what the rate will be. Fixing is an
optimal stopping problem, solved by backward induction over correlated
scenarios against `E[cost] + λ·CVaR₉₅[cost]`. Returns FIX NOW / WAIT / SPLIT
with the value of waiting, the probability a later date is cheaper, the regret
if that call is wrong, and the spot-versus-term efficient frontier that answers
the problem statement's actual objective.

**Risk Watch** — early warning across seven monitors: freight volatility,
regime shift, port congestion, predicted detention, import-plant coal stocks,
Bay of Bengal cyclones, and feed health. Every alert carries the numbers behind
it *and what it implies for a chartering decision*; an alert without an action
is noise.

**Port Watch** — live queue from the Paradip daily berthing programme, with 73
days of archived history. Real observed data, not a model.

**Market Cockpit** — commodity price history back to 1970 and the CEA
import-coal urgency signal.

**Data Provenance** — a live audit of what the platform holds and where it
came from.

## The honesty gate

The forecaster is measured on strictly walk-forward folds with an embargo,
against a random walk and a seasonal naive baseline, on two comparisons: CRPS
for the distribution and MAE of the median against the baseline's point
forecast. It may only claim an edge when it wins **both**, against **every**
baseline, with enough folds — the point comparison is what stops the platform
claiming skill on the strength of merely having drawn an interval.

Where that bar is not met the UI shows a **no edge** badge, and the timing
engine refuses to time the market at all: it returns the full feasibility and
cost arithmetic, which is real and useful, and says plainly that waiting on an
unmeasured signal is a gamble rather than a strategy. An unmeasured model is
treated as having no edge, not as fine.

The FFA forward curve is the other benchmark the strategy document demands. It
is exchange-licensed, we do not hold it, and `SYNTHETIC_DATA.md` forbids
manufacturing one to beat — so the platform reports *benchmark unavailable*
rather than a fabricated comparison. `app/ml/evaluate.py` enforces that in code.

## Data honesty

Every ingested row carries `source_name`, `source_url`, `retrieved_at` and
`is_synthetic`. The ingestion layer **refuses to write a synthetic row whose
source is not declared in [`SYNTHETIC_DATA.md`](SYNTHETIC_DATA.md)**, and a
test asserts the disclosure cannot drift out of date.

There are now **three** kinds of number on the screens, badged differently:
**real** (fetched from a named publisher), **synthetic** (generated by us,
declared), and **modelled** (computed by a model from either). Model output
deliberately does not carry the provenance mixin — a forecast is not an
observation — so the "% real" badge counts ingested rows only and a forecast
can never inflate it.

The platform holds one disclosed synthetic source: eight years of freight
history for the CDFI coal routes, used for model development because the real
CDFI history endpoint is subscriber-gated and the free one yields two days.
Its level is anchored to the real assessment and its cycle is driven by the
real World Bank coal price; it lives under `SYN_`-prefixed series codes and
never mixes with the real series. See
[`SYNTHETIC_DATA.md`](SYNTHETIC_DATA.md) for the full method and
[`DATA_SOURCES.md`](DATA_SOURCES.md) for every source.

## Running it

```bash
# one-time
py -m venv .venv
./.venv/Scripts/python.exe -m pip install -r backend/requirements.txt
cd frontend && npm install && cd ..

# fetch real data
./.venv/Scripts/python.exe scripts/backfill.py --all
./.venv/Scripts/python.exe scripts/backfill.py --adapter paradip --start 2026-06-01

# derive, fit, forecast, evaluate, alert
./.venv/Scripts/python.exe scripts/run_models.py

# run
cd backend && ../.venv/Scripts/python.exe -m uvicorn app.main:app --reload   # :8000
cd frontend && npm run dev                                                   # :5173
```

## Layout

```
backend/app/
  ingest/     one adapter per source, behind a caching base class
  domain/     loadable_tonnes.py (the physics), feasibility.py (the screen),
              alerts.py (the risk rules)
  ml/         panel + features (causal), quantile forecaster, conformal
              calibration, GARCH volatility, regime detection, waiting-time
              hazard model, walk-forward evaluation, daily pipeline
  opt/        scenarios.py (correlated draws), timing.py (optimal stopping)
  models/     SQLAlchemy schema; ProvenanceMixin on every *ingested* table
  api/        FastAPI routes
  data/
    raw/        archived source PDFs and workbooks, exactly as fetched
    reference/  port_constraints.yaml, vessel_classes.yaml
frontend/src/pages/   the six screens
scripts/      backfill.py (ingest), run_models.py (fit and alert)
```

## The engines

### Loadable tonnes — `domain/loadable_tonnes.py`

Given this vessel, berth, tide and cargo, how many tonnes can actually be
loaded, and if not, which constraint bound?

```
displacement(draft, rho) = [(lightship + dwt) - (summer_draft - draft) * 100 * tpc] * rho / 1.025
cargo = displacement - lightship - bunkers - constants
```

Four limits can bind and the engine reports which one did: draft (plus tide
where the port works vessels on a tide), deadweight, hold volume (low
calorific value coal cubes out before the marks), and the hard dimensional
rejections.

### Waiting time — `ml/waiting_model.py`

A discrete-time hazard model over 418 reconstructed port calls, 19% of them
censored. Censoring is the crux: a vessel still at anchorage when the archive
ends contributes everything it genuinely tells us — that it waited *at least*
that long — and nothing more. Dropping those rows or treating them as berthed
biases every estimate downward, which is the direction that would make the
platform under-price demurrage risk.

This is the most forecastable quantity in the system. Queueing behaviour is far
more predictable than freight rates, and it feeds the demurrage term in the
timing engine, which is often larger than the freight difference between two
routings.

### Entry timing — `opt/timing.py`

```
V(T) = fix_cost(T)                                  # deadline: must fix
V(d) = min( fix_cost(d),  E[V(d+1)] + carry(d) )    # earlier: fix or wait
```

Evaluated per scenario on the risk-adjusted objective, so a date with an
attractive mean but an ugly tail does not win. `carry(d)` is inventory carry
plus a stockout penalty scaled by the CEA days-of-burn signal — without it the
model would always wait, because optionality is free if delay costs nothing.

Scenarios are drawn through a Gaussian copula so freight, congestion and bunker
shocks move together. Independent draws would let good and bad news cancel and
produce a CVaR far too flattering to trust.

Feasibility gates everything: the constraint engine screens which vessels can
physically berth before any timing is attempted.

## Not built yet

- **Second congestion port.** One port's queue is not a market signal. Vizag is
  reachable but needs its own parser; this is the highest-value addition left.
- **AIS.** The tonnage-supply index in §9.2 of the strategy document is the one
  genuinely proprietary signal available, and nothing here uses AIS yet.
- **Stochastic MILP.** The contract-mix frontier is a grid search over term
  splits, not the two-stage MILP of §7.3. Pyomo and HiGHS are already declared.
- **Tides.** The engine takes tide height as an explicit input and defaults to
  zero. No tidal figure is invented anywhere.
- **Real freight history.** CDFI accumulates daily from now; once it passes 250
  observations the pipeline switches to it automatically and the synthetic
  development series stops being used.
